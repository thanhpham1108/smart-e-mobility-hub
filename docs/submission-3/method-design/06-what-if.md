# What-if Simulation — Method descriptions

**Owner:** Nguyễn Xuân An — 2452023; Submission 3 support: Phạm Nguyễn Công Thành — 2453175. **Use cases:** UC-W01–W05. [Class diagram](../class-diagram/what-if/06-what-if.puml) · [Inventory](../class-diagram/what-if/06-what-if-inventory.md).

## Data contracts

- `ScenarioDraft`: name, one or more hypothetical conditions, affected resource IDs, simulation period and assumptions. Conditions can represent arrivals, full/offline Hub, charging surge/point fault or concentrated vehicles.
- `NetworkSnapshot`: one consistent, timestamped read of Hub, Rental, Parking, Charging and Fleet state with source versions/freshness, captured under the shared application state lock. `copyForSimulation()` produces an isolated writable copy with a new `snapshotId` and `sourceSnapshotId` pointing to its immutable baseline. The copy is not published as live state.
- `SimulationResult`: predicted measures with baseline metadata. `Recommendation`: proposed action and expected effect, never an executable live command. An empty recommendation list means “No Intervention Required” when the result explains why.
- `SimulationComparison`: the differences between two completed runs plus warnings for different snapshots, assumptions, horizons, freshness or incompatible measures. It changes neither run.

| Class.method signature | Purpose | Input and output | Preconditions | Postconditions / state change | Errors / exception result |
| --- | --- | --- | --- | --- | --- |
| `SimulationService.configureScenario(draft: ScenarioDraft): WhatIfScenario` | UC-W01: validate and save a proposed scenario. | Draft → ReadyToRun scenario. | Authorized Operator; period valid; conditions supported; referenced resources exist. | Save conditions, affected resources, period and assumptions. No simulation or live change. | Invalid input, disappeared resource or save failure: no ReadyToRun scenario is published. |
| `SimulationService.runScenario(scenarioId: String): SimulationRun` | UC-W02: start a new run asynchronously. | Scenario ID → Queued run with run ID. | Authorized Operator; ReadyToRun scenario still valid. | Persist Queued run, obtain consistent baseline, copy it, simulate, evaluate and save a Completed result/recommendations; intermediate statuses follow state chart. No live module write. | Missing/inconsistent snapshot, timeout, engine/result/save failure: mark Failed when possible; never publish partial result as Completed. Retry creates a new run. |
| `SimulationService.getResult(runId: String): SimulationResult` | UC-W03: view predicted outcomes and baseline context. | Run ID → completed result and linked baseline metadata. | Authorized Operator; run Completed. | Read-only; display measures, assumptions, snapshot time/freshness and unserved demand. | Unknown, incomplete/failed run or missing result: report unavailable/incomplete; no invented measures. |
| `SimulationService.getRecommendations(runId: String): List<Recommendation>` | UC-W04: review proposed coordination actions. | Run ID → ordered recommendations or empty list with No Intervention Required outcome. | Authorized Operator; completed run and evaluation available. | Read-only; never invoke live Fleet, Parking or Charging mutations. | Missing supporting result: report unavailable. Changed live state is shown as a baseline warning, not silently applied. |
| `SimulationService.compareRuns(firstRunId: String, secondRunId: String [0..1]): SimulationComparison` | UC-W05: compare two completed runs or one run against its baseline. | First run ID and optional second run ID → deltas, baseline context and comparability warnings. | Authorized Operator; selected run(s) Completed and results readable. | If second ID is absent, calculate baseline measures from the stored immutable snapshot with the **same metric definitions and time horizon** as the run, then compare; otherwise compare two runs. Read-only; flag differing snapshot, horizon and assumptions. | Missing/incomplete run or incompatible/missing measures: reject comparison or mark affected measures non-comparable; do not fabricate deltas. |
| `WhatIfScenario.isReadyToRun(): boolean` | Guard simulation start. | No input → boolean. | Scenario has validated conditions/period. | Read-only; true only in ReadyToRun status. | Invalid/missing configuration returns false. |
| `NetworkSnapshot.copyForSimulation(): NetworkSnapshot` | Isolate scenario changes from the baseline and live state. | No input → deep copy. | Source snapshot is complete and internally consistent. | Copy receives a new `snapshotId`, records `sourceSnapshotId` of its immutable baseline, retains source versions and has independent state storage. | Copy failure or inconsistent source: fail run before applying any hypothetical change. |
| `SimulationRun.isCompleted(): boolean` | Guard result, recommendation and comparison reads. | No input → boolean. | Run has a valid lifecycle status. | Read-only; true only after results and recommendations commit together. | Unknown/invalid status returns false. |

The sequence diagrams name controller, validator, worker and repositories separately. This class diagram keeps the domain-facing `SimulationService` as one operation entry point; the asynchronous worker is an implementation detail inside the application process. The run lifecycle still follows the Submission 2 state chart.
