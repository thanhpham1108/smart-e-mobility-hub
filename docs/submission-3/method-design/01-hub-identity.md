# Hub & Identity — Method descriptions

**Owner:** Võ Hoàng Phúc Duy — 2452214

**Class diagram:** `../class-diagram/01-hub-identity.puml`

**Use cases:** UC-A01, UC-A02, UC-H01, UC-H02, UC-H03, UC-X01

The method signatures below match the operations shown in the class diagram.

| Class.method signature | Purpose | Input and output | Preconditions | Postconditions / state change | Errors / exception result |
| --- | --- | --- | --- | --- | --- |
| `User.updatePermittedProfile(email: String, phone: String): void` | Update permitted personal contact information while preserving identity and role. | `email`: permitted email value; `phone`: permitted phone value; returns `void`. | User has an existing profile and is authenticated. Identity fields and role are not editable through this operation. | Valid contact values replace the permitted profile fields. User ID and role remain unchanged. | Invalid email/phone format: reject the update and keep the existing profile unchanged. |
| `Session.isActive(now: DateTime): boolean` | Determine whether a session is currently valid. | `now`: current timestamp; returns `boolean`. | Session exists and contains its creation and expiry timestamps. | No persistent state is changed. Returns `true` only while the session is within its validity interval. | Invalid/missing session timestamps should result in an inactive session rather than granting access. |
| `MobilityHub` | No operations are defined directly on `MobilityHub` in this module. | — | — | Hub state is represented by its attributes and queried through `HubService`. | — |
| `AuthService.authenticate(identifier: String, credential: String): Session` | Verify user credentials and establish a session with the user's assigned role. | `identifier`: account identifier; `credential`: supplied authentication credential; returns a new `Session`. | Authentication request contains required credentials and the account exists. | On success, a session is created containing the authenticated user ID and assigned role. | Invalid credentials: authentication fails and no session is created. |
| `AuthService.authorize(session: Session, requiredRole: Role): boolean` | Check whether an authenticated session is permitted to perform a protected operation. | `session`: current session; `requiredRole`: role required by the operation; returns `boolean`. | Session must be present; the operation must specify the required role. | No persistent state is changed. Returns `true` only when the session is active and has the required permission. | Missing, expired, or insufficient-role session: return `false`; protected operation must not proceed. |
| `AuthService.endSession(sessionId: String): void` | End the current authenticated session. | `sessionId`: session to terminate; returns `void`. | Session exists or the request is safe to process idempotently. | The specified session is no longer usable for protected operations. Existing reservations, rentals, and charging requests remain unchanged. | Unknown/already-ended session: treat as an idempotent sign-out; no protected state is changed. |
| `HubService.findHubs(criteria: HubSearchCriteria): List<MobilityHub>` | Search and filter Mobility Hubs by location and required services. | `criteria`: location, search radius, and requested services; returns matching Hub list. | Search criteria contains a usable location. Current-location lookup has already succeeded or a manual location was supplied. | No Hub lifecycle state is changed. Matching Hubs are returned, or an empty list when none match. | Invalid criteria: reject the search. No matching Hubs: return an empty list so the UI can show a no-results message. |
| `HubService.getHubStatus(hubId: String): MobilityHub` | Retrieve the selected Hub's current operational and availability information. | `hubId`: selected Hub identifier; returns the corresponding `MobilityHub` status data. | Hub ID is supplied and the Hub exists. | No persistent Hub state is changed. Returned data includes vehicle availability, parking occupancy/capacity, charging-point availability, operational status, and `lastUpdated` freshness information. | Unknown Hub: return status-unavailable result/error. Partial upstream data: return available fields and mark unavailable information rather than inventing values. |
| `HubService.findAlternativeHubs(criteria: HubSearchCriteria): List<MobilityHub>` | Find other Hubs that may satisfy a failed reservation/search requirement. | `criteria`: location and required service/capacity criteria; returns alternative Hubs. | Original request has failed or requires alternatives; criteria identifies the requested area/service. | No reservation or booking is created. Returns candidate alternatives for the user to inspect/select. | No suitable alternatives: return an empty list. Selecting an alternative must trigger a fresh availability check; it does not itself confirm a booking. |
| `HubSearchCriteria` | Data object representing Hub search/filter requirements. | `location`, `radiusKm`, `requiredServices`. | Location and radius must be usable; required services may be empty when only location is required. | No state change. | Invalid radius/location: validation failure before Hub search. |
| `Location` | Data object representing a geographic location used for Hub search and display. | `latitude`, `longitude`, `address`. | Coordinates/address must represent a usable search location. | No state change. | Missing current location can be handled by the caller using manual location input, as defined by UC-H02. |
